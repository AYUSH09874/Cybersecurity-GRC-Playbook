# Templates and Checklists

Reusable starter artifacts for learning, tabletop exercises, and controlled internal use. Adapt each template to your organization’s approved methodology, legal requirements, contractual commitments, and evidence-handling rules before using it in production.

## Templates

| Template | Use it for | Key caution |
|---|---|---|
| [Risk register](risk-register-template.md) | Recording and tracking risks, owners, treatments, and residual risk | A score is a decision aid, not the entire risk decision. |
| [Evidence request list](evidence-request-list.md) | Making evidence requests specific, scoped, and trackable | Do not collect secrets, unnecessary personal data, or unrestricted production exports. |
| [Control test workpaper](control-test-workpaper.md) | Documenting a repeatable control test | Define the population, sample method, and conclusion; do not equate a screenshot with proof of operating effectiveness. |
| [Finding and remediation](audit-finding-remediation.md) | Turning an observation into an owned, verified corrective action | Validate root cause and remediation effectiveness before closure. |
| [Policy template](policy-template.md) | Drafting a controlled policy document | Confirm document owner, approver, exceptions, review cycle, and publication location. |
| [Vendor review checklist](vendor-review-checklist.md) | Performing a first-pass third-party security review | Tailor depth to data, access, criticality, and service dependencies. |
| [Standard document template](standard-document-template.md) | Keeping playbook chapters consistent | Explain the real workflow and artifacts, not only framework definitions. |

## Safe working practices

- Use fictional or properly anonymized data for public examples.
- Never commit passwords, API keys, tokens, private keys, customer evidence, or confidential audit reports.
- Record evidence location and access restrictions instead of copying sensitive evidence into GitHub.
- Mark fictional scenarios as fictional. Never present sample artifacts as evidence of a real certification or audit.
- Identify which framework version, assessment period, control owner, and organization scope an artifact covers.
